# fm1wifi: a WiFi driver for the FM-1, as a library

A driver for the WiFi core inside the M-VAVE FM-1's JieLi AC79 (WL82) chip, written from the hardware's facts
(docs/WIFI.md), not from JieLi's binary WiFi libraries. It is OPLBOX's, but written to be shared: any firmware on
the FM-1 can link it. Nothing in this directory includes a file from outside it, uses an OPLBOX global, or touches
a register itself.

**Status: stages 2-6** (docs/WIFI.md "Plan"). It powers the core up and down, reads and writes its MAC and baseband
registers, takes a diagnostic snapshot and checks RAM for writes by the hardware (stage 2, run on an FM-1), and
brings the radio up and calibrates it: PLL, a fresh trim, channel and TX power (stage 3, run on an FM-1). Stages 4-6
(docs/WIFI_STAGE4.md; host-tested, not run on an FM-1 yet): the MAC's defaults and an address, one frame in or out
through the FIFOs, a passive or active scan of a channel, joining an open network as a station. Networking (IP,
WPA2) is stages 7-8, in the layers docs/WIFI.md "Standalone library" lists.

## Files

| File | What |
| --- | --- |
| `fm1wifi.h` | the public API |
| `fm1wifi.c` | the driver (stages 2-6: power, radio, the frame FIFOs, the scan and join drivers) |
| `fm1wifi_frame.c`, `fm1wifi_frame.h` | the frames as data (stages 4-6): the RX parser, the scan list, the TX image, a station's management frames and its state machine; no register access |
| `fm1wifi_regs.h` | the register map: addresses and masks only (SDK `WL82.h`, Linux `rt2800.h`, facts from `wl_rf_common.a`; provenance at its top) |
| `fm1wifi_tables.h` | the radio's register facts as data, generated by `tools/wifi_ir.py` from your JieLi SDK (do not edit; docs/WIFI_STAGE3.md) |
| `fm1wifi_port.h` | what the library needs from the board: you implement it |
| `wpa_crypto.c`, `wpa_crypto.h`, `bearssl/` | WPA2 key primitives for stage 8 (PMK, PRF/PTK, AES key unwrap) on a BearSSL subset; not used by the driver yet |

## The API

```c
#include "fm1wifi.h"

int  fm1wifi_power_up(void);       /* clocks, resets, DMA set-up (about 55 us); keeps what it replaces */
void fm1wifi_power_down(void);     /* every register back to how power-up found it */
int  fm1wifi_mac_rd(uint32_t addr, uint32_t *v);   /* MAC registers: MAC_CSR0, MAC_SYS_CTRL, ... */
int  fm1wifi_mac_wr(uint32_t addr, uint32_t v);
int  fm1wifi_bbp_rd(uint8_t reg, uint8_t *v);      /* baseband, through BBP_CSR_CFG, bounded waits */
int  fm1wifi_bbp_wr(uint8_t reg, uint8_t v);
int  fm1wifi_diag_read(fm1wifi_diag *d);           /* power up if needed; MAC_CSR0, MAC_SYS_CTRL, BBP 0 */
void fm1wifi_pattern_fill(void *p, uint32_t n);    /* the RAM check: fill a free region before power-up ... */
fm1wifi_ramcheck fm1wifi_pattern_check(const void *p, uint32_t n);   /* ... count the bytes that changed */
const char *fm1wifi_strerror(int err);

/* stage 3 */
int  fm1wifi_radio_up(const fm1wifi_cal *cal, fm1wifi_radio *r);   /* the radio up and calibrated (about 1-2 s) */
int  fm1wifi_set_channel(unsigned ch);             /* 1-13 */
int  fm1wifi_set_power(unsigned level);            /* 0-6 */
int  fm1wifi_adc_peak(uint8_t *peak);              /* the receiver's ADC peak: reads only in the trim's loopback */
int  fm1wifi_channel_survey(unsigned ch, unsigned ms, fm1wifi_survey *s);   /* false CCA count, busy time over ms */
/* stages 4-6 (docs/WIFI_STAGE4.md; the frames themselves are fm1wifi_frame.h's) */
int  fm1wifi_link_up(const uint8_t mac[6], unsigned ch);   /* the MAC's defaults, the address, a channel */
int  fm1wifi_rx_ready(void);                       /* a received frame waits */
int  fm1wifi_rx_read(uint8_t *buf, uint32_t cap, uint32_t *n);   /* one frame, for fm1wifi_rx_parse */
int  fm1wifi_tx_send(uint8_t *img, uint32_t dma_len);   /* an image from fm1wifi_tx_image */
int  fm1wifi_scan_channel(unsigned ch, unsigned ms, int active, const char *ssid, fm1wifi_scan_list *l, fm1wifi_frames *fr);
int  fm1wifi_join(fm1wifi_sta *s, const fm1wifi_bss *b, unsigned ms, fm1wifi_frames *fr);   /* open networks */
```

`fm1wifi_radio_up` takes a calibration (`fm1wifi_cal_default`, or the FM-1's own crystal caps, PA trim and MCS gains
if you have them) and fills `fm1wifi_radio` with what it found (`fm1wifi.h`). It always makes a fresh trim. After a
TIMEOUT the fields hold what it had read: `got` has a bit for each value that was read (`FM1WIFI_GOT_*`), and a value
whose bit is clear was never reached.

Every call returns `FM1WIFI_OK` or an error (`FM1WIFI_ESTATE` when the core is not powered up, `FM1WIFI_ETIMEOUT`
when a bounded wait ran out, `FM1WIFI_EBUS` when the core answered nothing, ...; `fm1wifi.h`). Nothing blocks for
long and nothing needs an RTOS: call it from your main loop (or a task), never from an interrupt. The core's window
is never touched before `fm1wifi_power_up()`.

## Linking it into your firmware

1. Compile `fm1wifi.c` and `fm1wifi_frame.c` with `-I<this directory>` (C11; they need only `<stdint.h>`).
2. Implement `fm1wifi_port.h`: six functions, 32-bit register access to the WiFi blocks, the two WiFi bits of the
   shared `CLK_CON1`, a microsecond delay, what to do around the radio's trim, and the DMA address of a buffer. On **felucca-bsp**, use OPLBOX's
   [`firmware/hal/fm1wifi_port_bsp.c`](../hal/fm1wifi_port_bsp.c) as it is: it has nothing of OPLBOX's in it
   (compile it with felucca-bsp's `chip/` on the include path). On anything else, write your own, the same size.
   The host tests' port (`tests/wifi/sdio_model.c`) is a register model, if you want to test on a computer.
3. The radio's trim (stage 3) must not read the flash: the trim draws about 500 ms of high current and a flash fetch
   meanwhile reads corrupted data. The library puts the trim and what it calls in sections `.ram_code.fm1wifi`,
   `.ram_code.fm1wifi_data` and `.ram_code.fm1wifi_init`: your linker script must copy them into RAM (felucca's
   `app.ld` copies `.ram_code*`). The port's register access, delay and `fm1wifi_port_trim` must be in RAM too, and
   no interrupt handler that runs from the flash may run during the trim (felucca's port masks interrupts). On the
   FM-1 the flash's code cannot call RAM code directly (beyond the call range); the library calls across through a
   pointer itself, and your calls into it go to its public functions, which stay in the flash.
4. Stop the sound (or whatever else is timing-critical) before `fm1wifi_radio_up`; OPLBOX's test page stops its audio
   and waits until its output buffers hold silence.
5. `fm1wifi_where` (the step the library is in and its last register write, for a crash handler; `fm1wifi.h`) is in
   section `.noinit`: place it in RAM outside the start-up zeroing (felucca's `app.ld` has `.noinit`), call
   `fm1wifi_where_clear()` once at start, and have your fault handler show it when its magic is set. On the FM-1 the
   supply rails at M-VAVE's levels are worth raising before the radio comes up (OPLBOX: `platform_supply_full`,
   docs/WIFI_STAGE3.md "First run on an FM-1").

Interrupts (IRQ 52) join the port at stage 4. Each later stage keeps this directory's rule: no dependency on
OPLBOX, everything board-specific through the port.
